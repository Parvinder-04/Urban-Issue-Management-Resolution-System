# Task 15 — Deployment Guide

## Recommended option

**Render Web Service + persistent disk (Option A)**, chosen to keep the existing
SQLite safety guards, Alembic migrations and evidence storage intact. Managed
PostgreSQL (Option B) is judged higher-risk and not justified at this stage; free
ephemeral hosts (Option C) cannot preserve uploads or the database.

## What is prepared in the repository

- `deploy/Dockerfile` — Python 3.13 image, installs `backend/requirements.txt`,
  copies backend/frontend/scripts/deploy, creates an unprivileged user.
- `deploy/start.sh` — fixes disk ownership, builds/validates the public database,
  starts uvicorn on `$PORT`.
- `deploy/render.yaml` — Render Blueprint (Starter plan, 1 GB disk at
  `/var/data`, health check `/ready`).
- `deploy/seed/verified_departments.json` — verified Gurugram department
  directory only (11 departments, provenance preserved).
- `scripts/build_public_database.py` — idempotent public-database builder.
- `.dockerignore` — excludes databases, `.env`, uploads, tests and docs.

## Required environment variables (Render)

| Variable | Value |
|---|---|
| `UIMRS_ENV` | `production` |
| `UIMRS_FRONTEND_MODE` | `india` |
| `SECRET_KEY` | generated by Render (>= 32 chars) |
| `DATABASE_URL` | `sqlite:////var/data/uimrs_public.db` |
| `UPLOAD_DIR` | `/var/data/uploads` |
| `UIMRS_SEED_ADMIN_EMAIL` | operator e-mail (set once) |
| `UIMRS_SEED_ADMIN_PASSWORD` | strong initial password (set once) |

`ALLOWED_ORIGINS` is optional: when unset the application trusts
`RENDER_EXTERNAL_URL` automatically. Set it explicitly for additional origins.

## Persistent data

- `/var/data/uimrs_public.db` — live complaints, users, departments, audit log.
- `/var/data/uploads/evidence/` — accepted evidence images.
- `/var/data` is a Render persistent disk and survives restarts and redeploys.

## First boot behaviour

1. `deploy/start.sh` creates `/var/data` and `/var/data/uploads`.
2. `scripts/build_public_database.py` creates the database from the Alembic
   revision chain (no protected database is copied), seeds the 11 verified
   Gurugram departments, and creates the administrator account if the seed
   variables are present.
3. `ensure_bootstrap()` adds the system service user.
4. uvicorn starts on `0.0.0.0:$PORT`.

No historical Bengaluru rows and no synthetic `[EVALUATION TEST]` dataset are
seeded automatically. Evaluation records can be created through the normal
citizen workflow and are clearly labelled by their title.

## Health and readiness

- `GET /health` — liveness (always 200 when the process is up).
- `GET /ready` — readiness; runs the SQLite integrity check, validates the
  schema and confirms the Alembic revision is at head. Returns 503 otherwise.

## Backup and recovery

- Take a Render disk snapshot before any migration or seed change.
- Locally, copy `uimrs_public.db` with the SQLite backup API (the same helper
  used by `safe_backup_database`).
- Restore by replacing the file on the disk and restarting the service.
- Never copy `uimrs.db`, `uimrs_india_candidate.db`, `uimrs_india_dev.db` or
  `test_environment/uimrs_test.db` into a deployment.

## Security notes

- No secret is committed. `.env`, databases and uploads are git-ignored and
  excluded from the Docker image.
- Evidence images are never served as static files; downloads go through the
  authenticated issues router.
- CORS wildcards are rejected.
- Production startup fails when `SECRET_KEY` is missing, default or too short.

## Manual steps before deployment

1. Confirm the owner approves the Starter-plan cost.
2. Create the Render service from `deploy/render.yaml` or the dashboard.
3. Enter `UIMRS_SEED_ADMIN_EMAIL` and `UIMRS_SEED_ADMIN_PASSWORD`.
4. Wait for the first build and verify `/ready`.
5. Sign in as the administrator and provision officers through the portal.
6. Optionally create one clearly labelled `[EVALUATION TEST]` complaint to
   exercise the live workflow.
7. Run the Task 15 verification checklist in `docs/TASK15_TEST_REPORT.md`.

## Local validation performed

The image build has not been run in this environment. The equivalent local
validation is:

- `python scripts/build_public_database.py --destination data/public/uimrs_public.db`
  with `UIMRS_SEED_ADMIN_EMAIL`/`UIMRS_SEED_ADMIN_PASSWORD` set.
- Result: 11 departments, 2 users (system + admin), 0 issues, revision
  `0004_admin_audit_log`, `migration_state=initialized`.
- Re-running is idempotent (`already_current`, 0 new departments).
- Protected database hashes remained unchanged.
